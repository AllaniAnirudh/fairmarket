# Contributing to FairMarket

## What this project is right now

FairMarket is an open protocol for fair digital commerce, currently at the design stage. The most valuable contributions right now are criticism, questions, and concrete proposals, not code. Read [ARCHITECTURE.md](ARCHITECTURE.md) first, especially the open questions section.

## Ways to contribute

- **Design discussion.** Open-ended debate belongs in GitHub Discussions. Challenge the fee model, the dispute process, the extension system, the governance plan. Finding a hole is a contribution.
- **Issues.** For actionable items: errors in the docs, missing pieces of the design, specific questions that need answers.
- **RFCs.** For substantial proposals (a new vertical extension, a change to the core protocol, a fee policy change), follow [RFC_PROCESS.md](RFC_PROCESS.md).
- **Documentation fixes.** Typos, unclear explanations, broken links: open a PR directly.

## Licensing of contributions

Everything in this repository is under the Apache License 2.0. By contributing, you agree that your contributions are licensed under the same terms, including the patent grant in Section 3 of the license. This matters: the protocol's purpose is independent implementation by many parties, and the patent grant protects all implementers.

We use the Developer Certificate of Origin (DCO). Sign your commits with `git commit -s`, which adds a `Signed-off-by` line confirming you have the right to contribute the work under the project's license.

## Pull request process

1. For anything beyond small fixes, open an issue or discussion first so the direction is agreed before you write.
2. Keep PRs focused: one proposal or fix per PR.
3. Update the relevant docs in the same PR. Docs and spec text are the product at this stage.
4. All PRs need at least one review before merge. The `main` branch is protected.
