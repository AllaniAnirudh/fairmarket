# FairMarket Protocol Specification (draft v0.1)

## What this is

This directory holds the formal specification of the FairMarket protocol: an open, neutral rail for digital commerce across all verticals. If you implement what is written here, your implementation interoperates with every other compliant implementation.

## How to read it

- `01-problem.md` — the problem this protocol exists to solve
- `02-why.md` — why an open protocol, and why these design choices
- `03-what.md` — what the system is: actors, layers, and non-goals
- `04-identity.md` through `09-disputes.md` — the normative core. Every vertical uses these.
- `10-extensions.md` — the extension system, with the `food/v1` sketch
- `11-roadmap.md` — the phases beyond this spec: implementation, pilot, expansion

## Conformance language

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL are to be interpreted as described in RFC 2119. When this spec says a participant MUST do something, a compliant implementation has no choice. When it says SHOULD, there may be valid reasons to differ, but the reasons must be understood and documented.

## Status

Draft v0.1. Nothing here is final. Breaking changes are expected before v1.0. See `../VERSIONING.md` for how versions work, and `../RFC_PROCESS.md` for how to propose changes.
